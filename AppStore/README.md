# App Store metadata

The App Store Connect texts, kept in the project. Nothing is uploaded
automatically — open the file, copy the contents, paste it into the matching
field in App Store Connect.

The folders are named after the fastlane convention (`cs`, `en-US`, `en-GB`), so
if you ever decide to move to `fastlane deliver`, renaming `AppStore/` to
`fastlane/metadata/` is all it takes.

**This app is already live** (App Store ID `1634043414`, since 3 September 2022,
currently 1.1.0). So this is an *edit* of an existing record rather than a first
submission, and two of the fields below can be changed today without a new build.

## Where everything goes

App Store Connect → **Apps → J-Notes → iOS App → 1.1.1** (the version the
project is currently set to — `MARKETING_VERSION` in `notes.xcodeproj`). There is
a language switch at the top — every field is filled in separately for each
language.

| Field in App Store Connect | File | Limit | Currently | New build? |
|---|---|---|---|---|
| App Name | `<language>/name.txt` | 30 characters | 28 / 28 / 28 | yes |
| Subtitle | `<language>/subtitle.txt` | 30 characters | 29 / 28 / 30 | yes |
| Promotional Text | `<language>/promotional_text.txt` | 170 characters | 167 / 167 / 165 | **no** |
| Description | `<language>/description.txt` | 4000 characters | ~3000 | yes |
| Keywords | `<language>/keywords.txt` | 100 characters | 96 / 97 / 94 | yes |
| What's New in This Version | `<language>/release_notes.txt` | 4000 characters | ~1200 | yes |
| App Preview and Screenshots | generated by the scripts, see [screenshots.md](screenshots.md) | 1–10 images | 7 + video | **no** |

(The three numbers are `en-US` / `en-GB` / `cs`, in that order.)

**Promotional Text and the screenshots can be changed right now.** Everything
else is attached to a version and needs a build going through review. If you want
the cheapest possible improvement today, paste the promotional text and upload
the screenshots and the preview; the rest goes in with the 1.1.1 build.

Alternative names, subtitles and keyword sets, the reasoning behind the ones in
use, and what the competition looks like are in
[alternatives.md](alternatives.md).

Checking it. The limits are the easy half — the three checks after them are the
ones that catch real mistakes: a word paid for twice across two indexed fields, a
stray space in the keyword list, and a paragraph left wrapped at 80 columns.

```bash
python3 - <<'PY'
import os,re
lim={'name.txt':30,'subtitle.txt':30,'keywords.txt':100,
     'promotional_text.txt':170,'description.txt':4000,'release_notes.txt':4000}
bad=0
for loc in ('en-US','en-GB','cs'):
    d=lambda f:open(os.path.join('AppStore',loc,f),encoding='utf-8').read().rstrip('\n')
    for f,m in lim.items():
        n=len(d(f)); bad+=n>m
        print(f'{loc:6}{f:22}{n:5}/{m}', 'OK' if n<=m else 'OVER!')
    # a word in two indexed fields is paid for twice and indexed once
    t=lambda f:set(re.findall(r'[\wÀ-ſ]+', d(f).lower()))
    for a,b in (('name.txt','subtitle.txt'),('name.txt','keywords.txt'),
                ('subtitle.txt','keywords.txt')):
        ov=t(a)&t(b); bad+=bool(ov)
        if ov: print(f'{loc:6}DUPLICATED {a} x {b}: {sorted(ov)}')
    # a space after a comma silently costs one of the 100 characters
    if ', ' in d('keywords.txt'): bad+=1; print(f'{loc:6}KEYWORDS: space after comma')
    # App Store Connect keeps newlines - a paragraph has to be a single line
    L=d('description.txt').split('\n')
    for i,l in enumerate(L[:-1]):
        if (l.strip() and L[i+1].strip() and not l.isupper() and not l.startswith(chr(8226))
                and not L[i+1].startswith(chr(8226))
                and not l.rstrip().endswith(('.','!','?',':','…'))):
            bad+=1; print(f'{loc:6}DESCRIPTION line {i+1} wrapped mid-paragraph')
print('ALL CLEAN' if not bad else f'{bad} problem(s)')
PY
```

Run it from the repository root, not from this directory.

## Which localisations to create, and why three

Keywords never combine across languages — each localisation is its own search
index — but **most storefronts index two of them**, so a second language is free
extra keyword space in the same country rather than a different market.

| Storefront | Indexes | What that buys |
|---|---|---|
| United States | English (U.S.) + Spanish (Mexico) | `es-MX` would double the US pool |
| Czechia | **Czech + English (U.K.)** | `en-GB` doubles the Czech pool |
| United Kingdom, Ireland, Australia, New Zealand | English (U.K.) | `en-GB` is the primary there |

So the three folders here are:

- **`en-US`** — primary language of the record, and what most English storefronts
  read.
- **`cs`** — primary in Czechia, and the one worth the most effort per hour: the
  Czech notes market is tiny and mostly ad-supported (see
  [alternatives.md](alternatives.md)).
- **`en-GB`** — primary in the UK/Ireland/Australia/New Zealand *and* the second
  index in Czechia. Same description as `en-US` with British spelling, and a
  subtitle built around *secure* rather than *private*, because Apple's own search
  suggestions treat those as two separate phrases with two separate clusters of
  apps behind them.

`es-MX` is the obvious next one (it would double the US keyword pool for the cost
of a translation), and it is *not* included here: the app's interface is English
and Czech only, so a Spanish-speaking visitor would arrive at an English app.
That is allowed, and plenty of apps do it, but it trades conversion for reach.
Worth trying once there is enough traffic to measure the trade rather than guess
at it.

## Notes on the individual fields

- **App Name** — has to be globally unique, and it is the single strongest
  ranking signal. Today it is `J-Notes`, which Apple indexes as *j* + *notes* and
  nothing else, leaving 23 of 30 characters unspent on the strongest field in the
  listing. `J-Notes: Notepad, Lock, Draw` keeps the brand where the Home Screen
  name is and spends the rest on the three intents the long tail is actually
  searchable on. The Home Screen name stays `J-Notes`
  (`INFOPLIST_KEY_CFBundleDisplayName`), which Apple does not mind — the Home
  Screen name only must not differ in *meaning*, and a name that starts with the
  same word does not.
- **Subtitle** — **currently empty on the live listing.** It is the second
  strongest signal and the line people actually read in search results, and this
  is the largest single ASO gain available to the app. It adds the terms the name
  could not fit (*private*, *offline*, *no ads*) rather than repeating it.
- **Keywords** — separate with commas and **no spaces** (a space counts towards
  the limit). Do not repeat words already in the name or subtitle, Apple indexes
  those separately; that is why *notes*, *notepad*, *lock*, *draw*, *private* and
  *offline* are missing from the English lists.
- **Promotional Text** — the only field that can be changed without a new build
  and without review. Useful for seasonal or topical messages, and the one thing
  worth pasting in today.
- **What's New** — `release_notes.txt` describes what 1.1.0 actually brought,
  which is a great deal. The live 1.1.0 shipped with "Minor bug fixes and
  performance improvements" instead, and that cannot be edited without a new
  build — so 1.1.1 is the first chance to tell anyone. The text deliberately says
  "since 1.0.9" rather than naming a version, so it stays true whichever build it
  goes out with; add 1.1.1's own changes on top of it.

## Settings that are not filled in with text

**App Information** (shared across all languages):

- Primary Category: **Productivity** — where it already is, and where every app
  in the competition table sits.
- Secondary Category: **Utilities** — which is where Notepad: Easy Notes & Memos,
  Evernote and Zoho Notebook all put their second. Graphics & Design would be
  wrong despite the drawing: nobody browsing that category is looking for a
  notepad, and the drawing is a feature of the note rather than the point of the
  app.
- Content Rights: contains no third-party content
- **Gambling: No.**

`LSApplicationCategoryType` is **not** set in the project. It has no effect on the
App Store listing — it is the Mac App Store key — so nothing breaks, but setting
it costs one line and keeps the project honest about what it is:

```
INFOPLIST_KEY_LSApplicationCategoryType = public.app-category.productivity;
```

**Age Rating: 4+**, which is what the listing already carries. Every section of
the questionnaire is None: no violence, no chat, no links out, no contests, no
loot boxes, no unrestricted web access, no advertising. The one question worth
thinking about is **user-generated content**, and the answer is still None: the
notes are written by one person, for that person, on their own device. There is
no sharing between users, no server, no feed and no way for content to reach
anybody else except through the system share sheet, which the user starts
themselves.

**Pricing and Availability:** Free, all countries.

**App Privacy:** click *Get Started* → **"No, we do not collect data from this
app"**. The app has no networking code, no third-party SDKs, no StoreKit and no
analytics; notes live in a file inside the app's container with
`.completeFileProtection`, and settings live in UserDefaults (declared in
`notes/PrivacyInfo.xcprivacy`, reasons CA92.1 and 1C8F.1).

Be ready for the follow-up question about the three permissions — they are
*permissions*, not data collection, and none of them produces data that leaves
the device:

| Permission | Why | Where the result goes |
|---|---|---|
| Location (When In Use) | a note records where it was created, for the map | stored inside the note, on the device |
| Camera / Photos | a photo to draw on top of | stored inside the note, on the device |
| Face ID | unlocking notes the user marked as protected | nowhere; iOS answers yes or no |

A **privacy policy URL is still mandatory** — the text is ready in
[privacy-policy/](privacy-policy/), it just needs hosting somewhere (GitHub
Pages, a gist, your own site) and the URL pasted into the *Privacy Policy URL*
field.

**Support URL:** a mandatory field. The project's GitHub page or a simple page
with an e-mail address will do.

**Marketing URL:** optional, feel free to leave it empty.

**Encryption:** `INFOPLIST_KEY_ITSAppUsesNonExemptEncryption = NO` is already set
in the project, so the export compliance question never appears when the build is
uploaded.

**App Review Information** → the note for the reviewer is in
[review-notes.txt](review-notes.txt). The app needs neither an account nor a demo
login — leave *Sign-in required* switched off.

## Update procedure

1. App Store Connect → **Apps → J-Notes → + Version or Platform**, or open the
   version already in *Prepare for Submission*.
2. Check that all three localisations exist (App Information → language switch,
   top right): **English (U.S.)**, **English (U.K.)** and **Czech**. Only two
   are set up today if `en-GB` was never added.
3. Fill in the texts from this directory, one language at a time.
4. Screenshots and the App Preview are not in the repo — build them with
   `Tools/appstore_media.sh` and `Tools/appstore_compose.sh` and upload them, see
   [screenshots.md](screenshots.md). The iPhone slot this listing uses is
   **6.5"**, not the 6.9" the shots currently on the store were made at — moving
   between slots is a swap, not a mix. The iPad set is not optional for a
   universal app. `en-GB` has no media of its own; upload the `en-US` set into
   it.
5. Xcode → Product → Archive → Distribute App → App Store Connect → Upload.
6. Wait for the build to process (10–60 min), then select it in the *Build*
   section.
7. Re-check App Privacy and Age Rating (they carry over, but the questionnaire
   is occasionally re-asked).
8. **Add for Review** → *Submit*.

## One correction that has to be made regardless

The live description claims **"Rich Text Editing — Format your notes with bold,
italic, underline, and more"**. The app does not do that: the note body is a
plain `String` in a plain `UITextView`
([`notes/Views/Notes/UndoableTextEditor.swift`](../notes/Views/Notes/UndoableTextEditor.swift)),
and what the editor offers is undo/redo and a checklist button. Under guideline
2.3 that is inaccurate metadata. The description in this directory replaces the
claim with the two things that are real. Either ship that description or delete
the sentence — but do not leave it standing.
